# Versioning Scheme

## Overview

This project uses **Semantic Versioning** (SemVer) for releases:
- Format: `vMAJOR.MINOR.PATCH`

Example: `v6.1.0`

## Versioning Rules

| Component | When to Bump | Example |
|-----------|--------------|---------|
| **MAJOR** | First finishable release or fundamental rework | `0.x.x → 1.0.0` |
| **MINOR** | New features, mechanics, or content | `6.0.x → 6.1.0` |
| **PATCH** | Bug fixes, balance changes, polish | `6.1.0 → 6.1.1` |

## Version Generation

The version is automatically generated by qmake during build:

1. **Git commit count** → `VERSION_INT` (e.g., `v9629655`)
2. **Version components** → `SEMVER_MAJOR`, `SEMVER_MINOR`, `SEMVER_PATCH`
3. **Final version** → `SEMVER` (e.g., `6.1.0`)

### How to Release

1. **New Feature**: Bump MINOR
   ```
   SEMVER_MINOR: 0 → 1  (e.g., 6.0.0 → 6.1.0)
   ```

2. **Bug Fix**: Bump PATCH
   ```
   SEMVER_PATCH:  0 → 1  (e.g., 6.1.0 → 6.1.1)
   ```

3. **Fundamental Rework**: Bump MAJOR
   ```
   SEMVER_MAJOR:  6 → 7  (e.g., 6.1.9 → 7.0.0)
   ```

4. **First Stable Release**: Bump MAJOR from 0
   ```
   SEMVER_MAJOR:  0 → 1  (e.g., 0.1.0 → 1.0.0)
   ```

## Releases

Each version follows the **LVC** (Low-Velocity Change) workflow:
1. Code change
2. Build and test
3. Report
4. Permission for next slice
5. Commit
6. Tag
7. Push

## Release Files

Each release includes:
- `RELEASE_NOTES.md` - Changes and notes
- Git tag with version number
- Push to repository

## Tools Version

The `tools/` directory contains separate standalone tools with their own .pro files:
- `tools/room/` - Room builder
- `tools/maploader/` - Map loader
- `tools/data/` - Data loader
- `tools/editors/` - Editor tools
- `tools/*converter` - Data conversion tools

These tools are versioned separately and do not affect the main game version.
